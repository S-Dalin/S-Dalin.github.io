An experiment log that survives your own forgetfulness

date2026-07-28
tagsresearch, experiments
statustemplate

Six months from now, the person trying to reproduce your result is you — and you will have forgotten everything. Write the log for that person.

The template

I keep one log per experiment run, in plain Markdown next to the code. It has five sections, in this order:

# Experiment: <short name> — <date>

## Question
What am I trying to find out, in one sentence?

## Setup
- code version:    <git commit hash>
- data version:    <dataset + hash or date>
- config:          <link to config file>
- environment:     <machine, library versions>
- random seed:     <seed>

## Result
The numbers, verbatim. Plots as files, linked.

## Surprise
What did NOT match my expectation? (Most valuable section.)

## Next
The single follow-up this result suggests.

Why these five

Question forces you to admit what the run was actually for — this kills most "let me just try" runs that waste a week. Setup is the reproducibility contract: if any line is missing, the run doesn't count. Surprise is where the science lives; expected results confirm, unexpected ones teach.

The one rule

Log before you look at the results. Write the Question and Setup sections first, run the experiment, then fill in the rest. It's the only way to keep yourself honest about what you predicted.
